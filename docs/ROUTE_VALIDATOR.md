這是開發者端工具，不改正式網站。平常使用不需要開 Codex，也不需要 OpenAI API 金鑰。

## 最簡單的使用方法

1. 在專案資料夾雙擊 **`路線檢查.cmd`**。瀏覽器會開啟操作頁；命令視窗留著即可。
2. 選「六條試驗路線」或「全部已選用路線」，按 **開始檢查**。
3. 完成後按 **開啟異常報告**。先看合併異常與待補證據，需要看圖才展開個別路線。

關閉啟動視窗，工具就停止。報告是獨立 HTML，即使停止工具，仍可直接開啟 `.route-validator/reports/latest/index.html`。

目前這台電腦已有 Node.js。換電腦時需安裝 Node.js 24 或更新版本；本次實測版本為 24.22.3。核心只用 Node 標準函式庫，不用安裝 npm 套件。Windows 啟動檔已提供；其他系統可使用下方指令，尚未做跨作業系統實測。

Windows 啟動檔會依序尋找 PATH、一般安裝位置與 Codex 內附的 Node.js 24；這台電腦可直接使用內附版本，不必重複安裝。啟動檔使用 CRLF 換行，並在失敗時保留錯誤訊息視窗。

## 更新 Google Sheet

只使用 `Routes_順序校核` 與 `RouteNodes_順序校核`，不退回原始歷史分頁。

- 公開 CSV 可讀時，按 **更新 Google Sheet**。
- 私有表不會自動沿用 Chrome 或 Codex 的登入權限。本次公開 CSV 介面實測 HTTP 401，因此提供 CSV 備援。
- 在 Google Sheets 分別選取上述兩個分頁，依序使用「檔案 → 下載 → 逗號分隔值 CSV」，下載兩份檔案。
- 在工具按 **改用兩份 CSV 匯入**，各選一份，匯入後重跑。
- 也可請 Codex 用已連接的 Google Sheets 讀取並保存新快照；這一步有 AI 用量，離線驗證計算則不呼叫 AI。

兩份資料都成功解析後才替換目前快照；失敗保留舊資料。欄位按標題解析，空白 position 保留排除紀錄。原始取得快照及更正後快照分開保存。

## 新增路線

在兩個順序校核分頁加入新 Route ID、路線意圖、明確 Node ID 與 position，更新或匯入資料後即可檢查，不需修改程式的路線清單。

Node ID 以使用者指定的[節點總表](https://docs.google.com/spreadsheets/d/1qj9As7i-02V3MxdN1KuCtN_OkQAYYRHrimbxq6Jf5jk/edit?gid=102#gid=102)為基準。新路線若使用已存在的節點，可直接沿用；新實體尚無 ID 時，仍需先循專案的節點維護流程建立具來源的對照。工具不因同名、距離近或最短路徑可達而建立或更換全域 ID。

## 加入及重用 GPX

在操作頁展開 **加入 GPX 檔案／公開連結**，選檔並填對應路線、作者、來源網址。完整性、變體或交通方式不確定時留「尚未確認」，不能為了通過而猜填。

公開來源可直接下載；需要登入的來源請使用網站正常下載功能，再匯入，或請 Codex 協助操作已登入的瀏覽器。此工具不擷取登入 Cookie、帳密，也不繞過網站限制。

- 原檔依 SHA-256 保存，重複匯入相同內容會重用，並可關聯多條路線。
- 相同作者、來源行程、相同／反向形狀及近似轉載採保守合併，不能灌成多份獨立證據。
- 分日檔可以保存，但不會直接跨缺口接成一條「完整軌跡」。部分路段不能當整條路線證據。
- GPX 原始時間及高度保留；高度升降是未去除雜訊的觀測統計，不是 DEM 或上河實測時間。
- 原始 GPX、索引、解析快取及報告都在 `.route-validator/`，已排除 Git。搬電腦或備份時，把這個資料夾與專案一起帶走。
- 保存供本機比對不代表取得公開散布授權；本輪新下載原檔及其疊圖沒有加入正式網站。

## 如何閱讀結果

報告不要求逐列閱讀完整節點表。

| 結果 | 意義 |
|---|---|
| 符合自動檢查門檻 | 足夠獨立同走法來源，且順序、線形、首尾、資料與時間門檻齊備 |
| 有差異待處理 | 結構、來源或同走法比對有未解決差異；不是已核實錯誤 |
| GPX 證據待補 | 數量、完整性、品質或變體分類尚不足；不是路線通過 |
| 尚未展開 | 沒有有效序列，獨立列出，不強行生成、不計入通過 |

「最多候選匹配 23/23」不等於 23 個點都已驗證。同一來源仍可能缺首尾、在待確認距離帶、包含其他支線或無法唯一定位。

主異常清單將共用路段的缺邊／缺時間／缺線形合併。單一或低品質來源、未分類變體的局部差異放在證據明細，不逐段要求使用者裁定；至少兩組獨立、完整、無已知品質警訊的同走法來源呈現相同差異，才提升為主清單的疑似順序／線形問題。這仍不是自動修正授權。

R052、R057、R081 等既有候選已明列的手填時間政策，以精確 fromId／toId／種類核對後列為已確認例外，不重複要求決策；分鐘仍保持未知，不能因此宣稱來源時間完整。新出現或種類不符的缺時間路段不套用這個例外。

多組完整候選來源共同未匹配的位置另列摘要。若是指定起終點，保留步行意圖，不因參考 GPX 缺段就刪掉。

自動重排建議採保守範圍：節點沒有重複、位置可唯一匹配、首尾不變，且至少三組獨立完整同走法 GPX 支持相同順序；建議序列還必須有現行方向邊、來源時間及線形支持。符合時才填入 `proposals.json` 的 `after`。含折返／重複節點、缺點或需要重建路網的案例，不猜測修正後序列；原始資料一律不自動套用。

## 演算法與可重現性

- 重用 `preview/js/classic-route.js` 的精確有向邊、來源 span、反向及歧義檢查；不新增權威路網，不以最短路徑替換固定走法。
- GPX 1.0/1.1 使用受限、配對檢查的 XML 解析；拒絕 HTML、DTD、ENTITY、非法座標、缺時區時間與只有規劃路點的檔案。
- 每次經過有獨立 position。先找連續近點區間，保留每次到訪候選，再以全序列動態規劃匹配；沒有 beam search 的隱性截斷。
- 正反向分開比對；有多個可行經過位置、相鄰節點容差重疊、候選或計算超限時保留待確認。
- 分離軌跡及超過 500m 的觀測跳躍不補線；跨分段的匹配可供診斷，但不作無缺口通過證據。
- 雙向取樣比較來源 span 與實際匹配 GPX 片段；另比較行走長度，避免相同線形上的多走一遍被 Hausdorff 距離掩蓋。
- 初始近距離帶 30m、候選帶 100m、線形樣點間距 50m、線形距離門檻 30m；長度差門檻取 100m 與來源長度 25% 的較大者。這些是可調工程門檻，不是正確率或信心百分比。
- 至少三組合格獨立來源才可能通過。中斷、速度／時間警訊、來源重用、自身建立的路網線形、未分類變體等都不能自動算入完整同走法支持。
- Sheet、Node ID 基準、路網、幾何、GPX、設定與引擎內容均保留雜湊。相同路線輸入重用結果；路網異動採保守整體失效，不宣稱已完成依賴範圍最小重算。
- 計算上限達到會回報未完成，不將截斷結果當成通過。

PASS 只表示指定版本符合自動門檻，不代表即時開放、現地通行或新取得官方核實。工具不自動提升既有候選為 `verified`，不自動匯入正式路線。

## 程式入口與檔案

```powershell
# 開操作頁
node tools/route-validator.mjs

# 六條試驗路線；其他路線可用 --routes R001,R031
node tools/route-validator.mjs check --pilots

# 所有 Sheet 路線的資料檢查；沒有 GPX 的保持證據不足
node tools/route-validator.mjs check

# 更新、匯入或收錄（一般使用者可改用操作頁）
node tools/route-validator.mjs sync
node tools/route-validator.mjs import-csv --routes Routes_順序校核.csv --nodes RouteNodes_順序校核.csv
node tools/route-validator.mjs add-gpx --file reference.gpx --routes R031 --author 作者 --source https://example.com/reference
```
