# IDEA-003 第一階段 Preview（2026-11-12）

本試點從最新 `origin/main`（`39e2374`，v0.9.1）建立 `codex/idea-003-path-editor`。僅改 `preview/` 的執行期程式；正式入口、`js/`、正式資料及 main 不變。不合併、不發布 Mountain Planner 正式版。相關已讀議題：#6 iPhone 捲動、#10 手機拖曳、#12 快速加入；未找到既有 IDEA-003 Issue。

## 試用方式

開啟此分支的 `preview/unified-editor.html`，展開「行程地圖與 GPX」，勾選「編輯路徑模式」。可先從一般 DAY 選單加入已收錄節點，也可直接在地圖點位置。

1. 點空白地圖，查看 WGS84（緯度、經度）與 TWD97 / TM2 121 分帶（公尺）；可複製座標、命名、加入選定 DAY 或設為選定路段的控制點。分帶範圍外明示 TWD97 未取得。
2. 選 DAY 和路段，或在編輯模式點選地圖路段。點擊模式可改成連續插入控制點。拖曳橙色 44px 控制點，或從清單刪除、向前移動。
3. 自動模式使用原全域步行路網。控制點無全域身分，經過控制點的部分以指定折線表達；不吸附附近路網。手動直線模式直接連接端點與控制點。
4. 「重新計算選定路段」只對所選相鄰行程項目重跑自動尋路；如增加中間路網節點，預設隱藏。已指定直線或控制點的路段保留使用者幾何並更新統計。其他路段不變。
5. 展開「顯示於行程表的節點」取消中間節點勾選，再勾選即可還原。起終點保留顯示；地圖及 GPX 保留完整路徑。新自動尋路加入的中間節點預設隱藏；原匯入行程保留原本顯示方式。
6. 使用既有復原、重做、JSON、Excel、GPX 功能。合計列的時間不直接編輯，重新顯示中間節點後逐段修改。手動時間空白保持未知。

控制點清單的「同位置新增 DAY 終點」會明確把該座標作為另一個行程地點附加在當日末尾；不自動分割或分攤原路段時間。可同時保留控制點用途。手動點不寫回全域路網，也不因同名或座標接近取得官方 Node ID。

## 資料與相容性決策

- 沿用 `day.items`，增加手動點 `coordinate: [lon,lat]`、項目 `showInTable`，以及終點項目的 `pathEdit: {fromItemId, mode, controls}`。控制點只存在於該路段，無須寫入全域 Node ID。
- `pathEdit` 只對仍相鄰且 ID 相符的端點生效；移動、刪除、拆日改變端點時，不把舊控制點錯套到新路段。來源路段與未修改路段保留原資料。
- 切成手動幾何時，原方向上河時間另存 `pathOriginalIncoming`；新的手動時間維持未知或使用者輸入。切回原路網可還原來源時間；另存 `pathManualMinutes`，再次切回直線時保留手動估時。原本就是手動時間的路段不重設時間。
- 自動模式在一般加入時沿用全域 `shortestPath`。不存在可用步行路徑、且兩端有可靠座標和正確項目連接身分時，才產生明示的手動直線。既有已核對步行邊若缺來源線形，仍保留缺漏提示，不假裝已取得真實步道幾何。沒有座標的端點不生成位置，也不允許插入猜測線形。
- 顯示層用完整時間軸計算抵達時間，再合計隱藏節點的移動時間、已知上河時間、路徑距離及高程。原始分段係數、來源、方向時間與備註留在 JSON。Excel 備註標示隱藏點合計與手動水平距離；混合時間的上河欄只計有來源的部分。
- GPX 使用全部來源線形及手動折線作 track，各來源 span 分段、不橋接缺漏；行程定位點作 waypoint，手動來源與警示寫入描述。無可靠高程的手動段不輸出 `<ele>`。
- 手動線形使用球面座標水平距離累加，介面標示「含手動水平距離」。沒有沿任意線條可用的瀏覽器 DEM 取樣服務；現有 DEM 是預先建好的來源線形剖面，不能直接當任意位置高程 API。因此手動段高程為 null，混合全日升降也明示未取得；剖面保留已有資料並在手動區間留白。
- 暫存鍵 `mountain-planner.idea003-autosave.v1` 與正式版及原 Preview 隔離。跨版本使用 JSON 搬移；請不要把含本試點額外欄位的檔案再交給舊版編輯並假設它能完整維護新欄位。
- 沿用原捲動錨點、分頁 autosave、歷史快照。Popup 不自動平移地圖、不主動聚焦輸入，字體 16px；退出編輯模式不新增點。

## 限制與後續驗收

任意手動線條沒有 DEM 高程；缺定位的歷史中間點也不推估座標。跨未定位節點的來源 span 仍沿用原「跨未定位點合計」規則，不能憑空拆成各子段精確距離／升降。沒有實機 iPhone／Android 驗收證據，不能把窄螢幕測試宣稱為已修復所有 iOS 捲動問題。未包含 GPX 匯入、吸附、自由筆刷、自動分天或全域路網修改。
