# 上河資料驗證流程

## 目標
所有正式步程資料都能追溯到上河官方步程示意圖，且避免 OCR、方向與人工轉錄錯誤。

## 狀態
- `draft`：第一次轉錄，禁止作正式規劃依據。
- `checked`：已再次對官方圖檢查，但尚未完成最終逐筆人工稽核。
- `verified`：人工逐筆與官方原圖核對完成。

## 建議程序
1. 從上河官方頁面取得當前圖片 URL。
2. 第一次獨立轉錄所有有方向的步程。
3. 第二次重新看原圖核對，不參考第一次結果。
4. 程式檢查：重複 edge、0/負值、孤立節點、單向遺漏與衝突值。
5. 最終人工逐筆 Source Audit。
6. 將 route 與 segment 狀態改為 `verified`，記錄核對日期與 revision。
7. 上河官方若更新圖片，該 route 應重新降級為 `checked` 或 `draft` 後再驗證。

## 禁止來源
網友行程紀錄、部落格、GPX 推估、個人實走時間，只可作參考，不可覆寫上河原始分鐘數。
