# Mountain Planner 全圖路網導入路線圖

更新：2026-10-28，開發分支 `feature/v0.7-node-identity`，正式版維持 v0.6.2，PR #2 未合併。

## 資料範圍與圖組正規化

- 官方：G01 百岳總覽；G02–G20 共 19 個具有獨立編號的路線圖系列。來源：https://www.sunriver.com.tw/step2020.htm
- 使用者候選 JSON：24 個群組、869 筆去回候選路段。
- 對應方式：23 個候選群組分屬官方 19 圖系列；額外 `八通關越嶺` 沒有獨立 G 圖號，不得猜測官方編號。
- G03 對應 `郡大山`、`西巒大山`；G08 對應 `北二段`、`畢祿羊頭連峰縱走`；G09 對應 `合歡群峰`、`奇萊`、`屏風山`。其餘映射見 `data/candidate_group_mapping.json`。
- G13 `干卓萬群峰` 的 `萬里山西峰` 顯示名稱統一為 `火山`，僅限該圖組；時間不變，歷史文字保留在正規化映射與審核紀錄。

## 開發關卡與完成標準

### M1：圖組、名稱、候選雙向分鐘數標準化 — 已完成工具與現有修正
- 原始來源不變；合併使用者確認的去回時間，保留慢速／重裝的條件式參考值。
- 24 群組與官方圖系列對照，G13 名稱別名、額外路段集獨立標記。
- `tools/run_candidate_ingest.py` 一次執行 `apply_reviewed_times.py`、`normalize_candidate_groups.py`、`batch_hiking_pipeline.py`。
- CI 以合成資料做 24 圖組全流程測試；實際 869 筆私人資料後續更新時需重跑並保留來源 checksum。
- **未達成**：所有路段的正式來源證明。

### M2：官方步程來源核對與權利評估 — 未完成（主要障礙）
- 每個有方向的路段綁定所屬官方圖、可信的起終 Node ID、來源 URL、正反方向分鐘數、必要時特殊條件。
- 依高風險、同名、交界、分鐘衝突、車行／停步路段優先核實；沒有官方證據的不當作已驗證。
- 缺少或模糊的官方資料不強行填值，集中整理給使用者少量確認。
- 公開批次衍生資料前評估上河著作權與授權；無法公開時需另定可合法使用的資料來源或授權方案。
- 完成標準：預定要公開尋路的每條方向邊都有來源證據與發布權限狀態。

### M3：正式路網模型與跨圖 ID — 部分完成
- 現有 202 組人工確認關係、81 canonical node clusters 沿用；禁止靠中文同名推定節點相同。
- 選定唯一真實 Node ID，分離圖組群組、實體地點、時間方向邊、條件式估時。
- 匯入編譯工具只接受批准且標明步行的資料，拒絕車行、未確認或無來源路段。
- G17/G18 Preview 目前為 24 節點、46 方向步行邊；其餘候選尚未通過 M2。
- 完成標準：跨圖路徑不產生未核實捷徑，來源、去回時間與節點一致性均可追蹤。

### M4：全圖批次匯入及增量修正 — 部分完成
- 每次匯入產生路段差異（新增／刪除／分鐘調整／審核狀態調整），並留審核檔、回退方式。
- 不覆寫用戶自主輸入的日係數、實際規劃時間；路網更新與使用者計畫快照分離。
- 完成標準：通過批准門檻的批次版本可重建一致的路網；重建結果具可追溯版號。

### M5：主行程編輯器整合與使用者資料升級 — 未完成
- 以既有 Preview 所驗收的節點搜尋、加入、分日、手動節點、休息與回復/重做為基底。
- 整合圖組切換與跨圖連線，而不是常設兩套編輯器。
- 匯入舊 v1 JSON、既有 localStorage 自動儲存時保留圖組／節點；若產生歧義或資料已廢止，要提示而不是靜默重接路。
- 支援條件式慢速／重裝（標準分鐘不變、可套用、可手調）。
- 完成標準：單圖、跨圖、多日、改時間、備註及匯入匯出均可使用。

### M6：驗收與正式版發布 — 未完成
- 自動測試：每個方向時間、來源對應、同名節點、跨圖斷點、路徑方向性、匯入/匯出、undo/redo、效能。
- 視覺驗收：桌機、中寬、手機、日期、折疊、長路線操作；避免選點列異常伸縮。
- 測試版與正式版獨立部署；使用者明確驗收後才合併 PR #2。
- 完成標準：經確認可合法公開且來源核實的路網範圍已全部發布；正式版 v0.6.2 的舊行程不遺失。

## 關鍵風險與未解項

1. **候選不等於官方核實**：已把內部重複及已知方向衝突改正，但尚未完成 869 筆逐方向官方來源核對。
2. **授權**：需有公開衍生步程資料的合規依據，不能只靠本站可瀏覽上河示意圖。
3. **圖組與地點身份**：八通關越嶺是候選補充群組，必須依實際路段來源分派，不能虛構 G 編號。
4. **資料更新影響舊行程**：routeId、Node ID 改動需遷移或明確提醒，不可自動篡改行程。
5. **官方圖是時間參考**：實際路況、管制及行進時間仍需另行查核，規劃器不可宣稱現地導航保證。

## 下一步執行順序

3. 決定可公開來源及授權範圍，再將來源已核實且可合法使用的圖組編譯進獨立測試路網。

## 2026-10-28 自動執行進度追加

- `tools/compile_approved_routes.py` 與對應測試已建立。只允許明確核實、具有授權狀態的**方向**路段進入受控編譯結果；候選資料不會藉此直接上線。
- `tools/build_source_review_queue.py` 已整合 `tools/run_candidate_ingest.py`。完整來源檢查表包含官方圖組、方向、候選分鐘、通用名稱或補充群組警告，待核對／待授權皆預設阻擋。
- 實際對 869 筆私人修正後資料產生 1,718 個方向的來源待查清單，其中 162 個方向優先處理（通用名稱位置不明或補充圖組）。完整結果僅在私人稽核包，不把候選原始內容提交公開儲存庫。
- `unified-editor.html` / `js/unified-editor.js` / `data/unified-editor-manifest.json` 提供同一介面切換 G06 與 G17＋G18 局部驗證路網，使用獨立自動儲存。它仍是 Preview，尚未開啟其他未核實候選路段，不能視為 M5 完成。
- 開發版所有自動測試已通過；正式版 `main/index.html`、`main/js/app.js` 未更新。

### 後續實質阻礙及不應跳過的工作

1. 逐方向獨立核對官方來源圖與 1,718 個候選方向（可以依圖集中進行，但資料一致不等於原圖核實）；上河另有 G07、G09 更新版，需選定來源版本。
2. 來源圖的公開大量衍生利用需要完成授權／合法利用範圍確認；僅能連結來源網頁不等於已取得整套圖資公開衍生權。
3. 對於 G01～G20 以外候選「八通關越嶺」的 38 條方向紀錄，逐段找到對應來源圖，不能當成獨立正式圖號。
4. 整合 Preview 需再驗收切換圖組、匯入舊 v1 行程、手機與桌機操作；不能憑 CI 的靜態驗證宣稱實際瀏覽器操作已完全通過。
5. 只有完成來源、授權、資料相容性及使用者驗收後才能進入正式版。
